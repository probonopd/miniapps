# Strict egress allowlist + privacy (Fire OS 6, cronos)

Goal: user-installed apps keep internet; Amazon and preinstalled apps/daemons do
not; updates are impossible; privacy-invasive services are off - while the
camera and local discovery (Avahi/mDNS) keep working.

## Device-side files

| Path | Purpose |
|---|---|
| `/system/bin/amazonblock.sh` | builds the strict allowlist atomically (`iptables-restore -w --noflush`), verifies it, stops telemetry/smarthome daemons |
| `/system/etc/amazonblock.allow` | allowed UIDs: user-installed apps only, generated by `install-amazon-block.sh` |
| `/system/etc/init/amazonblock.rc` | `exec` in `on post-fs-data`, before netd and zygote; rerun on netd start and at `sys.boot_completed=1`; `seclabel u:r:adbd:s0` |
| `/system/etc/hosts` | blackholes 57 Amazon/Alexa/OTA names (second layer) |

## Allowlist model

`AMZBLOCK` is first in `OUTPUT` (v4 + v6) and ends in **REJECT**; the `OUTPUT`
policy is **DROP**, so a missing chain still means no network. Allowed:

- loopback
- UIDs in `/system/etc/amazonblock.allow` (user-installed apps)
- root and system UIDs only: DNS 53 tcp/udp, DHCP 67/68 (and DHCPv6 546/547), NTP 123
- ICMP / ICMPv6
- adbd replies (source port 5555) to private addresses only

Everything else - other traffic from root (0) and system (1000), Amazon service users (`trackerd`
5120, `smarthome` 5108, `keystore` 1017, `blemesh` 5027, `inlocservice`) and all
Amazon app UIDs - is rejected.

Consequences:

- **New user apps must be added** to the allow list (re-run
  `../scripts/install-amazon-block.sh`, or append the UID to
  `/system/etc/amazonblock.allow` and run `sh /system/bin/amazonblock.sh`).
- **adb over WLAN is open on purpose**: unauthenticated root for the whole LAN,
  which can also disable this firewall.
- Captive portals cannot be logged into.
- Android may show “no internet” (connectivity check runs as UID 1000); user
  apps still work.

## Telemetry / smarthome daemons stopped at every boot

`aal-metric`, `trackerd`, `dha_service`, `inlocservice`,
`halo-hub-broker`, `halo-logr`, `meshmgrservice`, `shblemeshd`,
`shlocalskillsd`, `smarthomewifid`, `amazonfiled`, `wifi_log_levels`,
`integrity_logger`, `whad_cc`.

Kept on purpose: `aal` (MediaTek display service: stopped, the backlight could not come back after a 0), `cameraserver` (video conferencing), `avahi-daemon`, `mdnsd`
(discovery), `securetime` (clock), `rpmb_svc`, `perfmonitord`, `dbus`.

## Install / re-apply

```sh
../scripts/install-amazon-block.sh        # regenerate allow list, install, apply
../scripts/install-amazon-hosts.sh        # hosts blackhole (idempotent)
../scripts/privacy-hardening.sh           # privacy settings/packages; camera stays on
```

Check:

```sh
adb shell 'iptables -S OUTPUT | head -2; iptables -S AMZBLOCK | tail -n 1'
adb shell 'iptables -S AMZBLOCK | grep -c "^-A AMZBLOCK"'   # compare: next line
adb shell 'sh /system/bin/amazonblock.sh want'                # v4 v6 expected
adb shell 'dmesg | grep amazonblock:'
```

Verified after reboot with WLAN off: 17 v4 / 16 v6 rules, loaded at 4.96 s.
Real traffic is not tested yet; see DOCUMENTATION §9.2.

## Undo

```sh
../scripts/uninstall-amazon-block.sh [--enable-updates]
```

then restore `/system/etc/hosts.bak-20261031` if wanted.

## Notes

- Camera and Avahi/mDNS are deliberately **not** disabled. Use
  `privacy-hardening.sh --disable-camera` only if ever needed.
- ICMP stays open for all UIDs (needed); HTTP/HTTPS from blocked UIDs is not
  possible.
